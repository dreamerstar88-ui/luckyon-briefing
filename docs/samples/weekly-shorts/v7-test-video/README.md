### 왜 30초에서 35초로 늘렸나

30초 판에서 **훅이 너무 빨리 지나가 읽히지 않는다**는 지적을 받았다. 훅이 2.6초뿐이라
보기 3개가 0.2초 간격으로 튀어나오고, 마지막 줄이 1.9초에 떴다가 0.7초 만에 사라졌다.

늘린 5초를 이렇게 나눴다.

| 구간 | 30초 판 | 35초 판 | 늘린 몫 |
|---|---|---|---|
| 훅 | 2.6초 | **5.0초** | +2.4초 |
| 되감기 | 19.2초 | 21.2초 | +2.0초 |
| 정답 | 3.8초 | 4.1초 | +0.3초 |
| 요약·루프 | 4.4초 | 4.7초 | +0.3초 |

### 훅 안쪽 — 다 띄우고 세워 둔다

훅은 **문구를 다 띄운 뒤 그대로 세워 두었다가 5.0초 시점에 다음 화면으로 넘어간다.**
등장 동작은 앞쪽 `HOOK_RV`(등장창) 안에서 끝나고, 뒤쪽 `HOOK_HOLD` 는 전부 정지 시간이다.

```js
const HOOK_HOLD=1.95;                        // 다 띄운 뒤 세워 두는 시간
const HOOK_RV=(HOOK[1]-HOOK[0])-HOOK_HOLD;   // 등장창 = 3.05초
const hs=t=>t/3.05*HOOK_RV;                  // 3.05초 기준 대본을 등장창에 맞춘다
```

| 훅 안쪽 | 30초 판 | 35초 판(초안) | 35초 판(현재) |
|---|---|---|---|
| 숫자 카운트업 | 0.05 ~ 0.62초 | 0.10 ~ 1.19초 | **0.10 ~ 1.00초** |
| 질문 2줄 | 0.72 ~ 1.02초 | 1.38 ~ 1.96초 | **1.05 ~ 1.50초** |
| 보기 ①②③ | 1.12 / 1.32 / 1.52초 | 2.15 / 2.58 / 3.00초 | **1.60 / 1.95 / 2.30초** |
| 마지막 줄 | 1.90 ~ 2.20초 | 3.73 ~ 4.31초 | **2.75 ~ 3.05초** |
| **다 뜬 뒤 정지** | 0.40초 | 0.69초 | **1.95초** |

`HOOK_HOLD` 값 하나만 지키면 훅 길이를 바꿔도 등장 동작만 줄거나 늘고 정지 시간은 그대로다.
다음 회차에 표지를 손볼 때 이 값부터 본다.

**한 가지 짚어 둘 것.** 보고서 §12-2 에는 정지된 인트로가 길면 이탈이 커진다는 기록이 있다
(7.6초 정적 인트로가 4.7~8.9초 구간 이탈 절벽을 만들었고, 그래서 3.2초 → 2.6초로 줄였다).
이번 훅은 5.0초지만 **처음부터 끝까지 계속 무언가가 움직인다** — 숫자가 올라가고, 질문이
올라오고, 보기가 하나씩 튀어나온다. 정적 인트로와는 다르다. 다만 이 판의 유지율은
실제로 올려 본 뒤에 확인해야 한다.

58.4초 판(9/7 제작)과 비교하면 되감기 구간이 42.8초에서 21.2초로 줄어 봉이 넘어가는 속도가
약 2배 빠르다. 사건 정지는 두 판 모두 5곳이고, 1.8초에서 1.5초로 줄였다.
사건이 요일당 하나씩이라 그래프 위에 고르게 퍼진다.

## 사건 표기

사건이 지나가면 그래프에 **세로 점선 + 번호 배지 + 사건 내용 세로 글씨**가 남는다.
글씨는 한 글자씩 똑바로 세워 위에서 아래로 쌓는다(`vtext()`). 오른쪽 여백이 좁으면
선 왼쪽으로 자동으로 넘어간다.

**그리는 순서는 세로 라벨 → 주가 선이다.** 주가 선이 라벨 위를 지나간다.
초안에서는 반대였는데(라벨이 선을 가림), 주인공은 선이라 순서를 뒤집었다.
`eventLines(...,'labels')` 를 `polyline()` 보다 먼저 호출한다.
마지막 요약 화면까지 ①댈러스연은 ②제조업지표 ③공장주문 ④서비스지표 ⑤고용지표 다섯 개가 남는다.
무엇을 골랐고 왜 그것만 골랐는지는 `사건선정기준.md` 에 있다.

## 숫자 표기

모든 숫자는 **자릿수 폭을 고정**해서 그린다 (`numT()`).
0~9 중 가장 넓은 글자 폭을 재서 모든 숫자를 같은 칸에 가운데 맞춤으로 넣는다.
카운트업·시계·가격이 매 프레임 바뀌어도 글자가 좌우로 흔들리지 않는다.
Pretendard 에는 고정폭 숫자 기능(`tabular-nums`)이 캔버스에서 안 먹으므로 직접 구현했다.

## 다시 만드는 법

```bash
node render.mjs --out=frames   # 프레임 1,050장, 약 70초
FF=node_modules/ffmpeg-static/ffmpeg
$FF -y -framerate 30 -i frames/f%05d.jpg -c:v libx264 -preset slow -crf 18 \
   -pix_fmt yuv420p -movflags +faststart silent30.mp4
# loudnorm 을 페이드보다 먼저 걸어야 끝이 제대로 무음이 된다
$FF -y -ss 20.0 -i lyria-build-v1.mp3 -t 35 \
   -af "loudnorm=I=-14:TP=-1.5:LRA=11,afade=t=in:st=0:d=3.0,afade=t=out:st=30.3:d=4.7:curve=ipar" \
   -ar 48000 -ac 2 bgm30.wav
$FF -y -i silent30.mp4 -i bgm30.wav -map 0:v:0 -map 1:a:0 -c:v copy \
   -c:a aac -b:a 192k -ar 48000 -ac 2 -shortest -movflags +faststart reel.mp4
```

5분봉 원본은 `../v6-nasdaq-week/data-nq-5m.json`.

## 화면 문구 — "되감기"를 쓰지 않는 이유

이 영상은 월요일부터 금요일까지 **앞으로 재생**한다. 뒤로 감는 장면이 없다.
그래서 화면에 나가는 말은 "되감기"가 아니라 **"다시 돌려보기"** 로 쓴다.

| 자리 | 문구 |
|---|---|
| 훅 마지막 줄 | 5분봉 1,179개, 지금부터 **다시 돌려봅니다** |
| 되감기 구간 머리말 | 나스닥100 선물 · 5분봉 **다시 돌려보기** |
| 마무리 CTA | 다음 주도 **다시 돌려 드립니다** |

코드 안의 변수명(`REPLAY`)과 이 문서의 구간 이름은 그대로 둔다. 화면에 나가는 말만 바꾼 것이다.

## 영어 병기와 자막

영어를 두 갈래로 넣는다. 하는 일이 서로 다르다.

| 갈래 | 어디에 | 보이는 방식 | 노리는 것 |
|---|---|---|---|
| **화면 병기** | 영상 그림 안 | 항상 보인다. 끌 수 없다 | 보는 사람이 바로 읽는다 |
| **자막 트랙** | 유튜브에 올리는 `.srt` 파일 | 시청자가 자막 버튼을 켜야 보인다 | 유튜브가 글자로 읽어 검색·추천에 태운다 |

### 화면 병기 — 고정된 한 자리

화면마다 영어를 끼워 넣으면 배치가 무너진다. 그래서 **자리를 하나로 고정했다.**
가는 구분선(y1468) 아래 y1524 에 34px 한 줄. 기존 배치는 건드리지 않는다.

| 구간 | 영어 한 줄 |
|---|---|
| 훅 | Nasdaq 100 futures, Mon open to Fri close. How deep was the drawdown? |
| 되감기 | 사건마다 한 줄 (예: ISM Services 55.4, forecast 54.3) |
| 정답 | Peak 29,571 to trough 28,927 — a 2.18% drawdown |
| 요약 | The week's low and high both landed in Korean evening hours |

**요약 화면만 예외다.** 그 자리에 손글씨 CTA(y1512)가 있어 겹친다. 그래서 요약에서는
제목 두 줄 바로 밑(y344)으로 올리고 구분선도 뺐다. 제목의 영어 부제처럼 읽힌다.

### 자막 트랙 — 구간을 영상과 맞춘다

`srt.mjs` 가 영상 타임라인 값(`HOOK`/`REPLAY`/`ANSWER`/`SUMM`, `HOLD`, 사건 인덱스)에서
자막 구간을 직접 계산한다. 손으로 시각을 적지 않으므로 다음 회차에 길이가 바뀌어도 값만 고치면 된다.

구간 경계: 0 / 5.00 / 9.77 / 14.47 / 19.16 / 23.65 / 26.20 / 30.30 / 35.00초 —
사건 라벨이 바뀌는 시점과 정확히 같다.

이 영상에는 말소리가 없다. 그래서 자막은 "들리는 말"이 아니라 화면에서 벌어지는 일을 글로 옮긴 것이다.
자막 버튼을 켜는 시청자는 많지 않겠지만, 유튜브가 글자로 읽을 수 있어야 영어권 검색·추천에 걸린다.
