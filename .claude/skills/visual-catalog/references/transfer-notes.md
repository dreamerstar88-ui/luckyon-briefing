# 남의 규격을 옮길 때 — 원칙과 실패 기록

**성공보다 실패를 먼저 적는다.** 같은 실수를 다시 하지 않기 위해서다.

---

## 원칙 넷

1. **파일을 열기 전에 계획을 내지 않는다.**
2. **무엇을 재는지 먼저 정한다.** "상자 폭"과 "글자 위치"는 다른 것이다.
3. **"이 기법을 쓰면 좋아진다"를 재지 않고 말하지 않는다.**
4. **카탈로그의 기법이 내 환경에 맞는다는 보장이 없다.** 규격 문서가 있다고 차트 규격이 있는 것도 아니다.

---

## 1. 규격 문서가 있다고 차트 규격이 있는 건 아니다 (2026-08-30)

Monocharts 에 `.agents/skills/amicro-design-system/SKILL.md` 가 있는 것을 보고
"차트 규격을 여기서 가져오면 된다"는 계획을 냈다. 열어 보니 목차가 이랬다.

```
1. 디자인 토큰과 팔레트          ← 일부만 쓸 수 있음
2. 표준 카드 구조                ← Amicro 웹사이트 카탈로그 카드
3. 카탈로그 내비게이션·필터        ← 웹사이트 UI
4. 마이크로 인터랙션·햅틱          ← 브라우저 진동 API
5. CLI 레지스트리 등록 규칙        ← 그 저장소에 컴포넌트 추가하는 법
```

**차트를 어떻게 그리는지는 없었다.** 차트 규격은 각 `.tsx` 안에 흩어져 있었다.
**목차만 봤어도 30초면 알았다.**

---

## 2. `tabular-nums` 는 절반짜리 처방이었다 (2026-08-30 · 릴스 축)

> 차트 노트가 아니라 **캔버스 릴스** 얘기다. 하지만 «재보지 않고 말하지 않는다»의 근거라 남긴다.

카운트업 숫자가 흔들려 «숫자 폭 고정»을 처방했다. 먼저 폰트를 실측한 것까지는 잘했다.

```
Pretendard Bold 100px  최소 46.9px(1) ~ 최대 66.0px(0) — 차이 19.1px
```

고정폭이 아니었고 흔들림은 실재했다. **그런데 효과를 재보니:**

| 자리 | 그대로 | 폭 고정 |
|---|---|---|
| 평가액 (오른쪽 정렬) | 67.2px | **70.9px** ↑ 악화 |
| 배수 (가운데 정렬) | 39.5px | **50.4px** ↑ 악화 |
| 요약표 자릿수 어긋남 | 26.1px | 17.1px 개선 |

**원인을 분해했더니** 흔들림의 큰 쪽(42.3px)은 «자릿수가 늘어날 때»(`$99,999`→`$100,000`)였고
그건 폭 고정으로 **못 잡는다.** 잡히는 쪽(34.9px)이 작은 쪽이었다.

**게다가 한 번 틀린 답을 냈다.** 자리 예약을 넣고 재보니 0.0px 이 나와 "완전히 해결됐다"고 보고했는데,
그 0.0px 은 **예약한 상자의 폭**이었다. 눈에 보이는 것은 상자가 아니라 글자다.
오른쪽 정렬에서는 상자를 예약해도 **글자가 그려지는 좌표가 안 바뀐다.**

**결론: 적용하지 않았다.** 세 곳 중 두 곳이 나빠졌다.

## 3. 재현할 때는 원본 좌표를 그대로 읽는다

A/B 비교에서 "현재" 쪽을 대충 만들면 **허수아비를 때리는 것**이 된다.
원본에서 정확한 줄 번호와 값을 읽어 온다.

---

## 4. 렌더러를 고쳤으면 눈으로 본다

**프레임·카드를 뽑아 보기 전에 "완성"이라고 하지 않는다.** 실제로 나왔던 결함:

| 결함 | 원인 |
|---|---|
| 라벨이 화면 밖으로 잘림 | 바깥 오른쪽정렬인데 긴 라벨이 좌표를 음수로 밀어냄 |
| 아래 블록이 위 내용을 덮음 | 두 블록의 y 범위가 겹침 |
| 마지막 줄이 하단 푸터와 겹침 | 블록이 너무 아래에서 시작 |
| 라벨이 그림을 관통 | 라벨을 «가격이 가는 쪽»에 붙임 → **가격이 안 가는 빈 쪽**에 놓는다 |

차트 노트에서는 렌더 후 **16장을 전부 열어 본다** (절차서 5단계).
영어판이 한국어판보다 길어 넘치기 쉬우므로 특히 본다.
